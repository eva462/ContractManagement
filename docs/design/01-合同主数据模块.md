| 项目 | 内容 |
|---|---|
| 模式 | **本地开发**，不含生产部署与移动端发布 |
| 闭环 | 手工录入 → 合同台账 → 查看/编辑 → 上传附件 → 操作留痕 |
| 上游 | [`00-总体设计.md`](00-总体设计.md)（**候选设计，未冻结**；本文与其冲突处以本文为准） |
| 日期 | 2026-08-27 |

## 1. 本模块边界

### 做

Vite + React 前端 · Fastify + Prisma 后端 · PostgreSQL（本地 Docker）· 本地磁盘存附件 · 本地账号密码登录。跑起来就是 `docker compose up -d db` + `npm run dev`。

### 不做（本阶段明确排除）

云服务器 · 域名 · HTTPS · Cloudflare Tunnel · TestFlight / Apple Business · Capacitor 打包 · 生产 CI/CD · 定时任务 · 邮件与推送。

### 保留可替换边界

这三处做成**接口 + 实现**的形式，换实现时业务代码零改动：

| 边界 | 接口位置 | 当前实现 | 以后可换成 |
|---|---|---|---|
| **API 地址** | `apps/web/src/config.ts` | `VITE_API_BASE_URL`，默认 `http://localhost:3100` | 任意域名；Capacitor 里改 env 即可 |
| **附件存储** | `apps/server/src/storage/provider.ts` | `LocalDiskStorage`（`./var/uploads`） | S3 / MinIO / 阿里云 OSS |
| **认证方式** | `apps/server/src/auth/provider.ts` | `LocalPasswordAuthProvider`（scrypt + JWT） | OIDC / SSO / 钉钉 / 企微 |

前端 Token 读写另有一层 `apps/web/src/auth/tokenStore.ts`，现在走 `localStorage`，以后换 Capacitor `Preferences` 只改这一个文件。

## 3. 状态确认清单

### 存储状态只有 4 个

| 状态 | 代码 | 含义 |
|---|---|---|
| 草稿 | `DRAFT` | 录入中，字段可以不全 |
| 履行中 | `ACTIVE` | 已生效 |
| 已终止 | `TERMINATED` | 提前解除 |
| 已归档 | `ARCHIVED` | 完结封存，只读 |

### 「已到期」不是存储状态，是派生展示态

由 `expiryDate` 实时计算，**不落库**：

- `ACTIVE` 且 `expiryDate < 今天` → 列表/详情显示 **已过期**
- `ACTIVE` 且 `expiryDate` 在 30 天内 → 显示 **即将到期**

这样本地开发不需要任何定时任务，也不会出现「状态字段和日期对不上」的脏数据。<sub>← 相比候选设计的改动，见 §6</sub>

### 流转规则

| 从 | 到 | 动作 | 谁能做 | 校验 |
|---|---|---|---|---|
| `DRAFT` | `ACTIVE` | 提交生效 | 经办人本人 / MANAGER+ | 全部必填字段齐全 |
| `ACTIVE` | `TERMINATED` | 终止合同 | MANAGER+ | 必填终止原因 + 终止日期 |
| `ACTIVE` `TERMINATED` | `ARCHIVED` | 归档 | MANAGER+ | 二次确认 |
| `ARCHIVED` | 归档前状态 | 解除归档 | ADMIN | 二次确认，强制留痕 |
| `DRAFT` | 软删除 | 删除 | 经办人本人 / MANAGER+ | — |

**铁律：只有 `DRAFT` 能删。`ACTIVE` / `TERMINATED` / `ARCHIVED` 永远不提供删除入口。**

## 4. 权限确认清单

**3 个角色**（候选设计的 `VIEWER` 只读角色本期不做，需要时加一个枚举值 + 一条守卫即可）。

| 操作 | STAFF | MANAGER | ADMIN |
|---|---|---|---|
| 查看台账 / 详情 / 留痕 | 全部合同 | 全部 | 全部 |
| 新建合同 | ✅ | ✅ | ✅ |
| 编辑合同 | 仅本人经办，且状态 ∈ {DRAFT, ACTIVE} | 全部，非 ARCHIVED | 全部，非 ARCHIVED |
| 删除合同（软删） | 仅本人经办的 DRAFT | 全部 DRAFT | 全部 DRAFT |
| 提交生效 | 仅本人经办 | ✅ | ✅ |
| 终止 / 归档 | ❌ | ✅ | ✅ |
| 解除归档 | ❌ | ❌ | ✅ |
| 上传 / 删除附件 | 仅本人经办，非 ARCHIVED | 非 ARCHIVED | 非 ARCHIVED |
| 下载附件 | ✅ | ✅ | ✅ |
| 用户管理 | ❌ | ❌ | ✅ |

**可见范围：全员可见全部合同**（保留环境变量 `CONTRACT_VISIBILITY=ALL|OWN`，改配置即可切成「只看自己经办的」）。

**归档即只读，ADMIN 也不例外。** 想改已归档的合同必须先「解除归档」，这样每一次对归档合同的改动都会在留痕里留下明确的解封记录，而不是被人悄悄改掉。

**落地**：后端每个路由挂 `requireAuth` + 行级权限判定（见 `apps/server/src/modules/contract/permissions.ts`）。前端隐藏按钮只是体验，不是权限 —— 每个接口都会再判一次。

## 5. 验收标准

逐条可勾选，全部通过即本模块完成。

### A. 环境

- [ ] `docker compose up -d db` 起 PostgreSQL，`npm run db:migrate && npm run db:seed` 建表填种子
- [ ] `npm run dev` 同时起后端 `:3100` 和前端 `:5273`
- [ ] 种子数据含 3 个账号：`admin` / `manager` / `staff`（密码均 `admin123`），各对应一个角色

### B. 手工录入合同

- [ ] 未登录访问任意页面 → 跳转登录页
- [ ] 新建表单按「基础/金额/日期/内部管理」四组展示，进入时自动带出当前用户为经办人
- [ ] 点「自动生成」按合同类型产出 `CG-2026-0001` 形式的编号，同类型同年份连续递增
- [ ] 手工填一个已存在的编号 → 保存报错 `合同编号已存在`，且错误定位到该输入框
- [ ] 「无金额」时金额输入框禁用；「含税/不含税」时金额留空 → 校验拦截
- [ ] 勾「长期有效」时到期日期禁用；不勾且留空 → 校验拦截
- [ ] 生效日期早于签订日期 → 校验拦截
- [ ] 存为草稿：只要有合同名称即可存 `DRAFT`，其余必填可空
- [ ] 提交生效：必填不全时列出**具体缺哪些字段**，不是笼统报错

### C. 合同台账

- [ ] 列表显示编号、名称、类型、对方单位、金额、签订日期、到期日期、经办人、状态
- [ ] 关键词框同时匹配合同名称、编号、对方单位

- [ ] 点表头按签订日期 / 金额 / 到期日期升降序
- [ ] 分页正确（每页 20 条，切页后筛选条件不丢）
- [ ] 金额右对齐、千分位、跟随币种符号
- [ ] `ACTIVE` 且已过期的合同显示「已过期」红标；30 天内到期显示「即将到期」黄标
- [ ] 筛选条件写进 URL query，刷新页面后条件还在

### D. 查看 / 编辑

- [ ] 详情页分区展示全部字段 + 附件区 + 操作留痕区
- [ ] 状态流转按钮独立于「编辑」，且按当前状态和当前用户角色决定显示哪些
- [ ] `staff` 登录时，别人经办的合同看得到但编辑按钮不出现；直接调 API 也返回 403
- [ ] `ARCHIVED` 合同全部字段只读，无编辑/上传/删除入口
- [ ] 终止合同弹窗强制填终止原因和终止日期，留空不能提交
- [ ] `manager` 看不到「解除归档」，`admin` 看得到

### E. 上传附件

- [ ] 支持 PDF / JPG / PNG / DOCX / XLSX，单文件 ≤50MB，单合同 ≤20 个
- [ ] 上传时选附件分类：合同正本 / 补充协议 / 附件 / 其他
- [ ] 传非白名单类型（如 `.exe`）→ 拒绝并提示
- [ ] 超 50MB → 拒绝并提示
- [ ] PDF 和图片能在页面内预览，其他类型给下载
- [ ] 下载文件名是原始中文名，不是哈希串
- [ ] 附件落盘路径按 SHA-256 分片，同一文件重复上传不重复占磁盘
- [ ] 删除附件同时删记录，且留痕

### F. 操作留痕

- [ ] 新建、编辑、状态流转、上传、删除附件、**下载附件**、登录成功、登录失败，全部产生记录
- [ ] 编辑只记录**真正变化**的字段，没改的字段不出现在 diff 里
- [ ] 详情页时间线倒序，显示人话摘要，例如
      `张三 将合同金额从 ¥100,000.00 修改为 ¥120,000.00，到期日期从 2026-12-31 修改为 2027-06-30`
- [ ] 点单条留痕可展开看字段级 before / after
- [ ] 留痕里的用户名是**写入时的快照**，改用户显示名后历史记录不变
- [ ] 业务写入失败时留痕也不落库（同一事务）——可用「故意让保存报错」验证
- [ ] 系统没有任何修改或删除留痕的接口

## 6. 与候选设计的 5 处偏离

| # | 候选设计 | 本模块 | 为什么 |
|---|---|---|---|
| 1 | `EXPIRED` 是存储状态，靠每日定时任务置位 | 「已到期」改为由 `expiryDate` 派生的**展示态**，不落库 | 本地开发没有常驻定时任务；也消除了「状态与日期不一致」这类脏数据 |
| 2 | `counterparties` 独立表 + CRUD | 一期用 `counterpartyName` 文本字段 | 相对方管理本身是一个模块的量。本地无真实数据，将来升级成 FK 的迁移成本≈0 |
| 3 | `dict_items` 数据字典表 + 维护界面 | 合同类型等用 TS 枚举常量 | 同上，字典维护是独立模块 |
| 4 | 4 个角色（含 `VIEWER`） | 3 个角色 | 3 个角色已能覆盖全部权限分支；`VIEWER` 加一个枚举值即可 |
| 5 | shadcn/ui 组件库 | Tailwind + 自写组件 | 少一层 CLI 和生成代码，组件完全可控；本模块界面数量不多 |

字段砍掉 14 个见 §2。
